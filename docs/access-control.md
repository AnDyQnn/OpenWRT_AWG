# Контроль доступа (кастомный firewall)

[← К содержанию](README.md)

Вкладка **«Доступ»** — это управление доступом устройств. По умолчанию открыт
**весь** интернет; здесь точечно запрещаем ресурсы — всем или конкретным
устройствам.

> Раздельное туннелирование (что идёт мимо VPN) — **другая сущность**, на вкладке
> [VPN](vpn-split-tunneling.md). Первое решает «через VPN или напрямую», второе —
> «пускать устройство к ресурсу или нет».

---

## 1. Группы и блокировки

Группа = набор сайтов + политика блокировки. Имя и описание — по желанию.

| Шаг | Действие |
|-----|----------|
| Создать группу | имя (лат/кир) + описание — можно пустую |
| Добавить сайт | впиши `youtube.com` — набор доменов сервиса **подтянется сам** |
| Политика | кому блокировать (см. ниже) |
| Сохранить | кнопка «💾 Сохранить группу» |

Карточка группы **сворачивается** кликом по заголовку.

### Политика блокировки (область по устройствам)

| Политика | Кого режет |
|----------|-----------|
| **не блокировать** | группа определена, но не действует |
| **всем** | блок для всех устройств сети |
| **только выбранным** | чёрный список — режет только отмеченным MAC |
| **всем кроме выбранных** | белый список — доступ только избранным, остальным блок |

Под капотом: домены группы резолвятся в IP (**ipset**, авто‑рефреш), блокировка —
`iptables` в цепочке `FORWARD` с матчем по **MAC** устройства.

## 2. Устройства и вечные адреса

Список собирается **сам** по всем устройствам в сети — вы только редактируете.

| Поле | Откуда |
|------|--------|
| Имя | автоматически из **DHCP‑hostname** (что устройство само о себе сообщает); можно переименовать |
| Закрепить IP | DHCP‑резерв по MAC — устройство всегда получает один IP |
| 🟢 / ⚪ | онлайн сейчас / только закреплён |

**Зачем резерв:** правила по устройству (по MAC) стабильны, плюс понятная адресация.

## 4. ⚠ Устройства за вложенным роутером

Правила по устройству работают, когда устройство **в нашем L2‑сегменте**
(подключено напрямую или через точку доступа в режиме **мост / AP**).

| Снизу стоит | Что видит шлюз | Пер‑устройство правила |
|-------------|----------------|------------------------|
| Точка доступа / bridge | реальные MAC всех устройств | ✅ работают по каждому |
| Роутер в режиме **NAT** | только **один** MAC роутера | ❌ правило на всю его подсеть целиком |

Роутер в режиме маршрутизатора **NAT'ит** — прячет клиентов за одним адресом,
их не различить ни по MAC, ни по IP. Для пер‑устройство контроля доп. точки
включайте в режим **«точка доступа / мост»**.

---

## 5. Как это сочетается с VPN

| Слой | Где | Что делает |
|------|-----|-----------|
| Раздельное туннелирование | вкладка VPN | через VPN или напрямую (маршрут) |
| Группы/блокировки | вкладка Доступ | пускать устройство к ресурсу или резать (firewall) |

Слои независимы: можно «youtube напрямую» (VPN) **и** «youtube заблокирован всем
кроме директора» (Доступ) одновременно.
