# Имплементационный бриф — как запускать это ТЗ (точка входа для реализации)

> Это **промпт/обёртка** над дизайном. Полная спецификация и обоснования — в
> [auto-update.md](auto-update.md) (разделы 1–16 + Приложения А–Д). Здесь — то,
> что нужно, чтобы начать кодить без переспрашивания решённого.
>
> **Как использовать дома:** дай агенту этот файл + `auto-update.md` и скажи

## 0. Контекст и роль
- Проект: OpenWRT_AWG — AmneziaWG-шлюз (Debian + Docker: `gw-awg`, `gw-dnsmasq`,
  `gw-webui`). Прод-дерево на хосте — `/opt/gateway` (не git-репозиторий).
- Состояние пользователя — плоские файлы (реальной БД нет): `/etc/awg-setup/*`,
  `/etc/amnezia/awg0.conf`, `/var/lib/misc/dnsmasq.leases` (полный список — §6).
- Локальная сборка/тесты — дома (есть тестовый VPN-конфиг). Прод
  `10.13.13.36` — **не трогать** без явной команды.

## 1. Жёсткие инварианты (нарушать нельзя — проверять в каждом PR)
1. **КОД ≠ СОСТОЯНИЕ.** Обновления/рефакторы меняют только код; пользовательское
   состояние не трогается напрямую, бэкапится до и восстанавливается при откате
   (§2, §6, §В.4). Никакой топологии/настроек «зашитых в образ».
2. **Железо-агностично (Д.6).** Никаких имён интерфейсов в коде/состоянии —
   только роли (WAN/LAN/VLAN), детект как в `wan-detect.sh`. Замена 100М→1Г или
   2→4 карт ничего не ломает.
3. **Прод не ронять.** Любое изменение на железе — через бэкап + проверенный
   откат + health-gate; допускается ребут, но с dead-man switch.
4. **Целостность артефактов.** Образы — по digest; скачанное проверять (sha256),
   потом грузить. webui privileged + docker.sock → мусор не грузить.
5. **Очистка — не вслепую.** Никогда `docker system prune -af` пока жив `:rollback`
   (§8). Порядок BACKUP→CLEANUP→APPLY→HEALTH→COMMIT/ROLLBACK строго (Прил.§7).
6. **Идемпотентность.** Все apply-скрипты пересобираемы и переживают повтор/сбой
   питания (маркер + guard на загрузке).

## 2. Решения УЖЕ приняты (не переобсуждать)
- **Адресный пул VLAN:** `100.64.0.0/10` (CGNAT) основной + `172.16.0.0/12` без
  `172.17/16`. **`10.0.0.0/8` запрещён** (его раздаёт VPN-сервер). Нарезка
  `100.64.<vlan>.0/24`, префикс настраиваемый.
- **DHCP:** фичу резервирования/имён оставляем как есть; срок аренды → **90d**
  (вариант A, §В.2): «постоянка + авто-чистка по неактивности» одной строкой.
- **VLAN — две модели поверх одной:** L3-политики сейчас (работают за любым
  Wi-Fi роутером), 802.1Q позже (для managed-свитча). Членство — **MAC→VLAN**;
  адрес внутри VLAN — DHCP + резервации по необходимости.
- **Egress — 3 тумблера:** «Разрешить VPN» / «Только интернет» / «Только
  локальная сеть». Доступ — отдельная ось: `isolated` + `reachable_from`
  (кейс 1С: `lan_only` + `reachable_from=all`).
- **Кнопки железа:** все 4 (Перезагрузить шлюз / Перезапустить сервисы /
  Выключить). Выключение — нужно, с усиленным подтверждением.
- **Обновления:** код из ветки **`upd-code`** (+ `VERSION`/`manifest.json`),
  образы предсобранные по digest (GHCR), **не собирать на проде**. Режимы:
  manual / nightly / scheduled. Креды git не нужны (репа публичная).
- **Бэкапы — фундамент**, делаются ПЕРВЫМИ (§6A): единые
  `gateway-backup.sh`/`gateway-restore.sh`, ежедневный таймер, UI.
- **Откат:** одно поколение (`:rollback`), `gateway-prune.sh`, dead-man switch.

## 3. Открытые вопросы — ПОДТВЕРДИТЬ до кода (спросить один раз)
1. Managed-свитч / VLAN-aware точки в офисе есть? → когда браться за 802.1Q.
2. Финальный VLAN-пул: `100.64.0.0/10` ок?
3. Имя ветки-канала `upd-code` — финал?
4. Ретеншн: образов отката K=1, бэкапов K=3 — ок?
5. Окно `nightly` (напр. 04:00–05:00) и поведение по TZ.
6. Где хранить «текущую версию»: `/etc/awg-setup/.version` (рекомендуется).
7. Тестовый VPN-конфиг для CI → положить в `secrets.TEST_AWG_CONF`.
8. Причина двойного ребута прода (Д.4) — выяснить (может относиться к отсутствию sysmon).
9. Политика пушей: прямо в `main` или ветка+PR на каждую фазу.

## 4. Порядок реализации (фазы + Definition of Done)

> Каждая фаза — отдельный PR, со своими тестами и прогоном `gateway-selfcheck.sh`.
> Не ломать прод; не начинать следующую, пока предыдущая не «зелёная».

**Ф0. Фундаментные фиксы (быстро).**
- Включить таймеры `awg-watchdog`/`sysmon` в инсталляторе (`enable --now`) +
  проверка в self-check (Д.4).
- Единый TZ контейнеров = хост (`/etc/localtime`+`TZ` в compose) (Д.4a).
- _DoD:_ в журнале единое время; watchdog тикает 5 мин; sysmon 1 мин.

**Ф1. Бэкапы (§6A) — фундамент.**
- `gateway-backup.sh` (tar состояния §6 + meta + sha256), `gateway-restore.sh`
  (проверка sha + pre-restore страховка), `gateway-backup.timer` (daily), UI-блок.
- _DoD:_ create→restore round-trip восстанавливает состояние побайтово; бэкап
  переживает rebuild.

**Ф2. DHCP-рефактор «топология → состояние» (§В.4).**
- Вынести `dhcp-range`/`interface` из образного `dnsmasq.conf` в генерируемый из
  состояния конфиг (через `conf-dir`). Аренда 90d.
- _DoD:_ настройки DHCP переживают пересборку образа; миграция текущего `br-lan`
  в «default».

**Ф3. Per-device «мимо VPN» (Приложение А) — прогревочная.**
- `gw-direct-clients.sh` (MAC→mark→`ip rule`), флаг `direct` в `rules.json`,
  тумблер в списке устройств, рефреш из watchdog.
- _DoD:_ помеченное устройство выходит под адресом провайдера; снятие возвращает в VPN.

**Ф4. VLAN L3 (Приложение Г).**
- `network.json` (две оси: `egress` + `isolated`/`reachable_from`),
  `gw-network-apply` (подсети, dhcp-range per VLAN, `ip rule` egress, NAT,
  FORWARD-изоляция + исключения).
- UI: список VLAN (имя/комментарий/egress/изоляция).
- _DoD:_ кейс 1С работает (lan_only + доступен всем); 3 тумблера egress рабочие;
  всё в состоянии → переживает «обновление».

**Ф5. Кнопки железа (Приложение Б).**
- API + `nsenter` reboot/poweroff/`compose restart`, модалки, журнал, только админ.
- _DoD:_ перезагрузка возвращает шлюз; выключение за усиленным подтверждением.

**Ф6. CI + автообновление (разделы 3–13).**
- GitHub Actions: build → тест на `secrets.TEST_AWG_CONF` → publish (GHCR +
  `upd-code` с `VERSION`/`manifest.json`).
- On-device машина состояний (§7): staging→backup→cleanup→apply→health-gate→
  commit/rollback; `gateway-prune.sh`; dead-man (`gateway-update-guard`); UI-вкладка
  «Обновление» (3 режима); `gateway-selfcheck.sh` (§9).
- _DoD:_ обновление и принудительный откат проходят round-trip с сохранением
  состояния; провал health-gate → авто-откат + уведомление с этапом.

**Ф7. 802.1Q (когда есть managed-железо).** Теги поверх той же модели данных.

**Ф8. Графическая карта сети.** Поверх готовой VLAN-модели.

## 5. Как проверять (Definition of Done общий)
`gateway-selfcheck.sh` (§9) — read-only, без мутации данных: контейнеры up,
туннель+handshake, endpoint не через awg0 и нет широких маршрутов `/1../7`,
панель 200, DNS, NAT/MSS, ACL применены, `rules.json` валиден, **таймеры активны**,
WAN/LAN определены (инвариант железо-агностичности).

## 6. Рабочий процесс
- Ветка на фазу (или по решённому в §3.9), маленькие PR, тесты обязательны.
- Прод — только по явной команде, с бэкапом и откатом.
- Коммиты по-русски, осмысленные; не пушить наружу без подтверждения (если не
  оговорено иное).
