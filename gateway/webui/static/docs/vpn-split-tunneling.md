# VPN и раздельное туннелирование

[← К содержанию](README.md)

Как работает загрузка ключа, нормализация, обход напрямую и авто‑сбор адресов.

---

## 1. Загрузка ключа и нормализация

Когда вы загружаете `.conf` AmneziaWG (файлом или текстом), шлюз:

1. Сохраняет **исходный** ключ как есть (для скачивания / разбора).
2. **Нормализует** `AllowedIPs` → `0.0.0.0/0, ::/0` — весь трафик по умолчанию
   идёт в туннель.
3. Применяет ключ и поднимает туннель.

```
Загруженный ключ                  Активный ключ
AllowedIPs = 0/2, 64/3, ...   →   AllowedIPs = 0.0.0.0/0, ::/0
(antifilter, 109 диапазонов)      (всё в туннель, рулит шлюз)
```

**Зачем:** маршрутизацией управляет **сам шлюз** (как умный МЭ), а не статичный
список в ключе. Это даёт:

| Плюс | Объяснение |
|------|-----------|
| Простой ключ | можно подкинуть хоть голый `0.0.0.0/0` |
| Динамика | адреса обхода резолвятся вживую, не протухают |
| Нет петли endpoint | `0.0.0.0/0` включает нативную fwmark‑магию `awg-quick` (см. ниже) |
| Защита от кривых ключей | любой AllowedIPs нормализуется |

> Скачать можно оба варианта: **текущий** (нормализованный) и **исходный**
> (как залили) — вкладка VPN → «Скачать конфиг».

## 2. Раздельное туннелирование (обход напрямую)

Некоторые ресурсы должны идти **мимо** VPN: банки, госуслуги, локальные сервисы
(они часто ломаются или блокируют иностранные IP туннеля).

**Принцип простой: вписываешь ссылку — адреса собираются сами.**

```
Вписал «vtb.ru»  →  шлюз резолвит  →  195.242.82.0/24, 195.242.83.0/24
                                       маршрут через WAN (мимо VPN)
```

| Действие | Результат |
|----------|-----------|
| `+ Напрямую` → ввести ссылку | создаётся ресурс, адреса собираются автоматически |
| `+ ещё ссылка` внутри ресурса | добавить домен (тоже авто‑резолв) |
| `↻ адреса` | перерезолвить (IP сайтов меняются) |
| Можно вписать и подсеть | напр. `195.242.82.0/24` — добавится как есть |

Маршрут ресурса (домены вживую + сохранённые `/24`) более специфичен, чем
`0.0.0.0/0`, поэтому **выигрывает** — трафик идёт напрямую.

**Авто‑обновление адресов.** У сайтов меняются IP, поэтому:

| Что | Период |
|-----|--------|
| Маршруты обхода (`gw-access-routes`, резолв доменов вживую) | каждые 5 мин (watchdog) |
| Сохранённые адреса в ресурсах (для отображения / экспорта) | раз в час (фоновый поток панели) |
| Вручную | кнопка «↻ адреса» у ресурса |

Ничего настраивать не надо — для «смертных» всё автоматически.

## 3. Авто‑сбор обхода из ключа («дырки»)

Антифильтр‑ключ устроен как `0.0.0.0/0` **минус дырки**, где дырки = адреса,
что шли напрямую. Шлюз умеет **развернуть это обратно**:

```
Ключ: AllowedIPs = 0/2, 64/3, ... (109 диапазонов)
          ↓ complement (дополнение)
Дырки: 213.59.252.0/22, 195.242.82.0/23, 185.169.155.0/24, ... (6 шт)
          ↓ авто-сбор
Ресурсы раздельного туннелирования
```

| Когда срабатывает | Как |
|-------------------|-----|
| **Автоматически при загрузке ключа** | дырки собираются в список обхода |
| **Кнопкой** «📥 Собрать обход из ключа» | пересобрать вручную |

**Консолидация и дедуп** (чтобы не было нагромождения правил):

- узкие диапазоны **схлопываются** в широкие (`213.59.253/254.0/24` → `213.59.252.0/22`);
- то, что уже есть в списке, **повторно не добавляется**;
- идемпотентно — повторный сбор ничего не плодит.

> Блок «Обход, зашитый в ключ — N диапазонов» на вкладке VPN показывает именно
> **дырки** (реальный обход), а не сырой AllowedIPs.

## 4. Импорт / экспорт обхода

| Кнопка | Действие |
|--------|----------|
| **⬇ Экспорт JSON** | выгрузить список обхода (имена + адреса), читаемый JSON |
| **⬆ Импорт JSON** | загрузить список (для переноса между шлюзами / бэкапа) |

Формат:

```json
{
  "version": 1,
  "resources": [
    { "name": "Госуслуги", "desc": "gosuslugi.ru / ЕСИА",
      "domains": ["gosuslugi.ru", "esia.gosuslugi.ru"],
      "cidrs": ["213.59.252.0/22", "109.207.0.0/18"] }
  ]
}
```

**Стандартный шаблон.** На свежем шлюзе список обхода подсевается из вшитого
`split-default.json` (базовый RU‑набор: госуслуги, банки и т.п.). Дальше
пользователь правит сам.

## 5. Endpoint всегда мимо туннеля (нет петли)

Многие antifilter‑ключи включают адрес самого VPN‑сервера в `AllowedIPs` (напр.
endpoint `212.109.x` внутри `212.0.0.0/8`). Без защиты пакеты к серверу пошли бы
**через ещё не поднятый туннель** → петля, хэндшейк не проходит.

Лечится автоматически на двух уровнях:

1. **Нормализация в `0.0.0.0/0`** включает fwmark‑магию `awg-quick`:
   `ip rule … suppress_prefixlength 0` + `not from all fwmark 0x… lookup 51820`
   — помеченные пакеты туннеля идут через WAN сами.
2. **`awg-up`** при каждом подъёме добавляет `/32`‑маршрут к endpoint через WAN
   и **проверяет**, что endpoint реально пошёл не через `awg0`.

Диагностика, если хэндшейк жёлтый: команда `gateway-vpn-debug` на шлюзе.

---

## 6. Режимы VPN

| Режим | Значение |
|-------|----------|
| `vpn` | туннель активен, свежий хэндшейк |
| `fallback` | VPN‑сервер недоступен → трафик напрямую, попытка восстановления каждые 5 мин |
| `manual_off` | выключен вручную (кнопка «Выключить VPN») |
| `no_config` | ключ не загружен |
