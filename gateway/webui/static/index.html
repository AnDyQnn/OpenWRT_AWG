Раздельное туннелирование

Что идёт напрямую мимо туннеля (банки, госуслуги, локальные сервисы). Остальное — через VPN. Впиши только ссылку — её адреса соберутся сами и замаршрутизируются. Адреса перерезолвятся автоматически раз в час (кнопка «↻ адреса» — вручную). Исходный ключ содержал — диапазонов.

Обход, зашитый в ключ — 0 диапазонов (дырки)

Эти адреса в ключе шли напрямую (дырки в AllowedIPs). При загрузке ключа они собираются в список выше автоматически — с дедупом и схлопыванием. Кнопка — пересобрать вручную.

Управление доступом устройств. По умолчанию открыт весь интернет. Создай группу, добавь в неё сайты (адреса подтянутся сами) и укажи, кому её резать — всем или конкретным устройствам. Настройка самого VPN (что идёт мимо туннеля) — на вкладке VPN, резервы адресов и имена — на вкладке Сеть.

Группы и блокировки

Группа = набор сайтов + кому блокировать. Имя и описание — по желанию. Впиши адрес (youtube.com) — набор доменов сервиса подтянется сам, ничего разворачивать не надо.

Импорт / экспорт правил

Весь набор (группы с блокировками, устройства, раздельное туннелирование) одним JSON — для переноса между шлюзами или бэкапа.

Питание и обслуживание

Управление шлюзом из панели. Перезагрузка/выключение разрывают связь через туннель на время недоступности. Доступно только администратору, действия пишутся в журнал.

Перезапуск сервисов — мягко (VPN/DHCP/панель, без перезагрузки ОС). Перезагрузка — шлюз вернётся сам через ~1–2 мин. Выключение — после него включить шлюз можно будет только физически (удалённо — нет), требует ввода слова «выключить».

SSH-доступ (консоль администратора)

Вход в shell сервера по SSH. Со стороны интернета (WAN) порт закрыт фаерволом — заходить только из локальной сети или через VPN-туннель. Нестандартный порт уменьшает шум от ботов.

Текущий порт: —

Смена порта подтверждается паролем администратора. Текущие SSH-сессии не оборвутся; новый порт — для новых подключений. После смены подключайся к новому порту: ssh -p ПОРТ root@192.168.88.1.

Консоль и SSH — пароль и ключи

Доступ к shell сервера по SSH (логин root). Два способа входа — можно использовать любой или оба: по паролю или по SSH-ключу.

Быстрый старт

  1. Подключи кабель провайдера в любой порт ПК — WAN определится сам.
  2. Подключи другой порт к роутеру / коммутатору / ПК — это будет LAN (раздача).
  3. Открой http://192.168.88.1 и зайди (admin / admin).
  4. Вкладка VPN → загрузи .conf AmneziaWG.
  5. Готово — весь трафик идёт через зашифрованный туннель.

Шлюзу неважно, что на входе и выходе: провайдер может быть кабель/PPPoE, потребитель — роутер, коммутатор или один компьютер.

Полная техническая документация — вкладка «Документация» (архитектура, сборка, установка, VPN, доступ, диагностика).

Как читать вкладку «Сеть»

WANПорт к провайдеру — отсюда приходит интернет.
LAN (br-lan)Мост раздачи, IP 192.168.88.1. Сюда подключаются устройства.
VPN (awg0)Виртуальный интерфейс туннеля. IP вида 10.x.x.x.

Скорость (сейчас) — живой поток в этот момент (↓ скачивание, ↑ отдача), считается по приросту трафика. ↓ RX всего / ↑ TX всего — суммарно принято/отправлено с момента загрузки.

Устройства и их скорости

Вкладка «Сеть» показывает всех, кто получил адрес по DHCP: IP, MAC, имя и до какого времени аренда.

Колонка «Скорость (сейчас)» — живой поток по каждому устройству (↓ скачивание, ↑ отдача). Сразу видно, кто грузит канал или у кого просадка.

Если у устройства 0 — оно просто сейчас ничего не передаёт (простой). Как пойдёт трафик — появятся реальные цифры.

Доступ и фильтрация — кастомный межсетевой экран

Шлюз — это умный МЭ. По умолчанию открыт весь интернет; на вкладке «Доступ» вы точечно запрещаете ресурсы — всем или конкретным устройствам. Это не то же, что раздельное туннелирование (то — настройка VPN, на вкладке «VPN»).

ГруппаНабор сайтов + блок-политика в одном. Создаёшь группу (имя/описание — по желанию, латиница или кириллица), добавляешь сайты по одному. Вписал youtube.com — весь набор доменов сервиса подтянулся сам, ничего разворачивать не надо.
Кому блокироватьУ каждой группы: не блокировать · всем · только выбранным (чёрный список устройств) · всем кроме выбранных (белый список — доступ лишь избранным).
УстройстваСписок собирается сам по всей сети — ты редактируешь. Закрепляешь постоянный IP по MAC (DHCP-резерв) и имя — правила по устройству стабильны.

Под капотом: домены группы резолвятся в IP (ipset, авто-рефреш), блокировка — это iptables с матчем по MAC устройства. Раздельное туннелирование и доступ — разные сущности: первое решает, идёт ли трафик через VPN, второе — пускать ли устройство к ресурсу.

Устройства за вложенным роутером

Правила по устройству работают, когда устройство — в нашей сети (подключено напрямую или через точку доступа в режиме «мост / AP»). Если снизу стоит обычный роутер в режиме NAT/маршрутизатора, шлюз видит только один его MAC — все за ним выглядят как одно устройство. Тогда правило применяется ко всей подсети этого роутера целиком. Для пер-устройство контроля доп. точки включайте в режим «точка доступа / мост».

Весь набор правил можно выгрузить/загрузить одним JSON (кнопки внизу вкладки) — для переноса между шлюзами или бэкапа.

Встроенная консоль

Вкладка «Консоль» — полноценный терминал самого шлюза прямо в браузере (как обычная консоль, с приветствием и подсказками). Это удобный способ администрировать шлюз без отдельного SSH-клиента.

  • Двойная авторизация: сначала вход в саму панель, затем внутри консоли — повторно те же учётные данные панели (тот же логин/пароль, что и при входе в дашборд).
  • Подсказки команд справа — клик подставляет команду в консоль (gateway-status, docker ps, awg show, журнал, аренды, температура).
  • Доступна из LAN и через VPN; защищена авторизацией панели.

Как читать журнал

OKУспешное событие (VPN восстановлен, туннель поднят).
WARNПредупреждение (VPN недоступен, переключение на прямой).
ERRОшибка (не удалось поднять туннель, упал сервис).
INFOИнформация (ручные действия, старт сервисов).

Журнал ведётся в /var/log/awg-watchdog.log, обновляется автоматически. Время — местное: ставится по интернету (NTP), часовой пояс определяется автоматически.

Failover — защита от сбоев

Система самовосстанавливается на нескольких уровнях:

  • При каждой загрузке — переопределяет сеть, восстанавливает настройки (можно менять железо/порты).
  • Docker restart — упавший сервис (VPN, DHCP, панель) поднимается сам.
  • Watchdog (5 мин) — VPN упал → прямой интернет → попытка восстановить.
  • Sysmon (1 мин) — следит за сервисами, рестартит, чистит память.
  • Еженедельно — отчёт и авто-перезагрузка по воскресеньям.

Даже если VPN-сервер ляжет — ты не потеряешь интернет, трафик пойдёт напрямую и вернётся в туннель, когда сервер поднимется.

Установка на диск

Образ записывается на USB через Rufus (режим DD Image) и грузится на целевом ПК.

  1. При первой загрузке с USB запускается текстовый установщик.
  2. Он находит внутренний диск и спрашивает подтверждение.
  3. Копирует систему и перезагружается — дальше всё работает из коробки.

Консольный дашборд на самом ПК: команда gateway-status или watch -n3 gateway-status.

Частые вопросы

Не открывается дашборд? Проверь, что подключён к LAN-порту шлюза (или к роутеру за ним). Из интернета панель закрыта.

VPN жёлтый (failover)? Сервер недоступен — проверь endpoint, систему сама пробует переподключиться каждые 5 минут.

Поменял сетевую карту? Просто перезагрузи — порты определятся заново.

У устройства скорость 0? Значит оно сейчас ничего не качает (простой) — это норма. Появится трафик — пойдут реальные цифры.

Время в журнале правильное? Да — оно ставится по интернету (NTP), а часовой пояс определяется автоматически (по умолчанию Москва).
