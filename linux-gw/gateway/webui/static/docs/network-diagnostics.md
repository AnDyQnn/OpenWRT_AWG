# Диагностика сети: журнал сети и интернетометр

[← К содержанию](README.md)

> Два инструмента, чтобы понять, **почему «режется интернет»**: журнал сети
> показывает, что происходило с каждым портом (отвалы кабеля, пониженная
> скорость, реальная загрузка), а интернетометр меряет, сколько канал даёт
> прямо сейчас. Всё считается из живых данных шлюза — заданных заранее цифр нет.

---

## Журнал сети

Где: панель → **Журнал** → карточка **«Журнал сети»** (сверху вкладки).

### Период

- Кнопки **Сутки / Неделя / Месяц / 3 мес / Год** — последние N дней.
- Кнопка с датами — **свой календарь**: один день (два клика по нему или
  «Показать») или промежуток (клик по началу, клик по концу). «Сегодня»,
  «Вчера», «Сбросить». Будущие дни и дни до начала журнала неактивны.
- Стрелки **‹ ›** рядом — предыдущий / следующий день.
- Состояние на начало выбранного дня учитывается: если порт «застрял» на
  пониженной скорости накануне, день начнётся уже с этого.

### Сводка сверху

| Плитка | Что значит |
|--------|-----------|
| **Интернет-порт** | скорость линка WAN сейчас (с каким согласовался с роутером провайдера) |
| **Отвалы WAN** | сколько раз за период пропадал сигнал в кабеле провайдера |
| **На пониженной скорости** | сколько времени WAN работал медленнее обычного для него (например, 10 вместо 100) |
| **Без линка** | суммарное время, когда кабеля «не было» — интернета не было у всех |
| **Обычный максимум WAN ↓** | типичная пиковая загрузка канала: медиана суточных пиков за 30 дней (считается из истории) |
| **Последний отвал** | когда, на каком порту и сколько длился |

### Общий график «Скорость интернета по портам»

- **Линии** — реальная скорость по каждому порту: сплошная ↓ (к офису),
  пунктир ↑ (из офиса). У каждой роли своя гамма (WAN — синие, LAN —
  фиолетовые, VPN — бирюзовые, прочие порты — жёлтые), у каждого порта —
  свой оттенок. Линии включаются и выключаются кликом по легенде.
- **Полупрозрачные полосы поверх графика** — внештатные события, с подписью сверху:

| Полоса | Событие |
|--------|---------|
| 🟨 жёлтая | порт работал на пониженной скорости линка |
| 🟥 красная | отвалы линка (близкие склеены: «отвалы WAN ×5») |
| 🟩 бирюзовая | пропадал VPN-туннель (перезапуски по 1–3 с не считаются) |
| ▨ штриховка | шлюз был выключен дольше часа |

- **◆ ромб** — замер интернетометра на уровне измеренной скорости.
- **Цифры в рамках** — пики скорости.
- **Наведите курсор** — подсказка покажет среднюю и пиковую скорость каждого
  порта в этот момент и все события рядом с точным временем.

История скорости пишется с момента установки версии 2.12.4. Отвалы и
пониженная скорость видны за **весь срок журнала шлюза** (обычно месяцы) — они
берутся из журнала ядра.

### Таблица портов и детализация

Под графиком — все порты: что сейчас, сколько отвалов, без линка, на
пониженной скорости и проблемные периоды с датами. Кнопка **«Подробнее»** (или клик по строке)
раскрывает детализацию порта:

| Что | Как читать |
|-----|-----------|
| Драйвер, MAC, MTU, дуплекс, норма линка | паспорт порта |
| Средняя / пиковая ↓ ↑, передано | нагрузка за выбранный период |
| Отвалов, без линка, на пониженной | проблемы за период |
| **Смены линка** (с загрузки) | норма — 1–2 (включение). Десятки — кабель «моргает» |
| **Ошибки CRC / приёма** | 0 — сигнал чистый. **Растут — повреждён кабель или разъём** |
| Потеряно пакетов | заметный рост — перегрузка или проблемы с портом |
| Всего с загрузки ↓ / ↑ | трафик порта с момента включения шлюза |
| График порта | скорость только этого порта, поверх — его события |
| Последние события | отвалы с временем, длительностью и скоростью после |

### «В какое время суток случаются отвалы»

Распределение отвалов WAN и LAN по часам. Если почти все — днём, а ночью
тихо, это почти всегда физика: кабель задевают или двигают, роутер
провайдера греется под нагрузкой.

### Как по журналу найти причину

| Видно | Вероятная причина | Что делать |
|-------|------------------|-----------|
| Частые отвалы WAN по 1–3 с | кабель / разъём / порт роутера провайдера | переткнуть в другой порт роутера, затем заменить кабель |
| Жёлтые полосы: WAN «застревает» на пониженной скорости | плохо обжатый кабель (не хватает пар) | заменить кабель; перезагрузка шлюза лечит лишь до следующего отвала |
| Ошибки CRC растут | повреждённый кабель / разъём, помехи | заменить кабель, проложить подальше от силовых линий |
| Отвалы только днём | физическое воздействие или нагрев | проверить, где лежит кабель и как стоит роутер |
| Отвалов нет, а скорость низкая | канал провайдера / перегрузка | интернетометр; включить «Распределение скорости» |

## Интернетометр

Где: панель → **Сеть** → карточка **«Интернетометр»**.

Замер скорости и пинга **самим шлюзом** — без влияния Wi‑Fi и компьютера:

- **Сервисы:** Яндекс (ближайший узел их CDN), 2ip (их площадка, ближайшая по
  IP), Cloudflare (международный ориентир).
- **Каналы:** **напрямую** через провайдера и **через VPN**.
- Скорость считается по байтам самого теста (не по счётчикам порта), поэтому
  трафик других устройств замер не искажает.
- Каждый замер ≈ 20 с на сервис и канал. Пока идёт — интернет в офисе
  заметно занят; через VPN трафик замера идёт через VPN-сервер.
- Под результатами — **история замеров**; на графике журнала сети они видны ромбами.

Как читать: **все сервисы показывают мало** — узкое место у провайдера или в
кабеле; **мало только один** — проблема на стороне этого сервиса. Через VPN
обычно чуть меньше, чем напрямую, — это нормально.

## Под капотом

| Что | Где |
|-----|-----|
| Отвалы и скорость линка | журнал ядра (`journalctl`), сообщения драйверов «Link is Up/Down» |
| Пропадания туннеля | журнал `dhcpcd` (awg*) |
| Выключения шлюза | `journalctl --list-boots` |
| История скорости | служба `gw-netmetrics`: счётчики портов раз в 5 с, раз в минуту запись в `/var/lib/awg-setup/netmetrics.db` (поминутно — 3 дня, по 15 минут — год). Подхватывает **все** порты сама: WAN, порты моста, туннели awg*/wg*/tun*, прочие |
| Счётчики ошибок | `/sys/class/net/<порт>/statistics`, `carrier_changes` |
| Интернетометр | `gw-speedtest.py` (только стандартный Python); история — `/etc/awg-setup/speedtest-history.json` |
| API | `GET /api/netlog?days=N` или `?start=ГГГГ-ММ-ДД&end=ГГГГ-ММ-ДД`; `GET/POST /api/speedtest` |
