# Безопасность

[← К содержанию](README.md)

> Шлюз стоит на границе сети, поэтому защищён по умолчанию: снаружи (из интернета)
> закрыт, внутри — под наблюдением. Этот раздел объясняет, как это работает и что
> можно настроить. Всё — на странице **Система → Безопасность**.

---

## 1. Фаервол хоста

Самозащита самого шлюза (не путать с правилами для клиентов — те в [Контроле
доступа](access-control.md)):

- **Со стороны интернета (WAN) шлюз закрыт** — извне нельзя достучаться ни до
  панели, ни до SSH. Разрешены только ответы на исходящие соединения и получение
  адреса от провайдера (DHCP).
- **Изнутри (локалка/VPN)** — панель и SSH доступны.
- Включена защита от подмены адресов (anti-spoofing, `rp_filter`) и SYN-флуда
  (syncookies).

**Как админу попасть в панель**, если снаружи всё закрыто? Через тот же VPN, по
которому ходит трафик: подключаешься к туннелю — и ты «внутри», панель доступна.
Белый IP и проброс портов не нужны.

---

## 2. Защита от перебора паролей (fail2ban)

Следит за попытками входа — в **панель** и по **SSH**. Логика подбора пароля
распознаётся автоматически:

- **5 неудачных входов** с одного адреса → этот адрес **блокируется** (по умолчанию
  на 1 час). Повторные блокировки — дольше.
- Блокировка пишется в **Журнал событий**.

### Защита от случайной самоблокировки

> Частый страх: «а вдруг оно залочит меня или важное устройство?»

**Не залочит.** Блокируются **только публичные (интернет) адреса**. Все приватные
диапазоны (`10.x`, `192.168.x`, `172.16–31.x`) — в «белом списке» навсегда. А
админ всегда заходит из локалки или по VPN, то есть с приватного адреса. Поэтому
ни ты, ни рабочее устройство в локальной сети заблокированы быть не можете —
блокируется только атакующий снаружи.

## 3. Монитор атак (дашборд)

На **Дашборде** блок «Безопасность» показывает состояние в реальном времени:

| Состояние | Когда | Что значит |
|-----------|-------|------------|
| 🟢 **Штатно** | угроз нет | обычная работа |
| 🟡 **Подозрение** | 2+ неудачных входа с одного адреса | кто-то пробует пароли |
| 🔴 **Атака** | 5+ неудачных входов | идёт перебор; адрес блокируется fail2ban |

После блокировки атакующего состояние возвращается в 🟢 **Штатно** (угроза
нейтрализована). Рядом — счётчики заблокированных адресов и попыток.

**Разблокировать** адрес (если ошибся живой человек) можно кнопкой в списке
заблокированных — с подтверждением.

## 4. Роли (кто что может)

Две роли (задаются при создании пользователя в **Доступ → Пользователи**):

- **Администратор** — полный доступ: настройки, VPN, устройства, консоль, SSH,
  пользователи.
- **Модератор** — **только просмотр**: метрики, дашборды, журнал событий и
  контакты для связи. Менять настройки, открывать консоль и трогать безопасность
  не может. Удобно дать дежурному/наблюдающему, не отдавая управление.

Ограничения проверяются и в интерфейсе, и на сервере (обойти через прямой запрос
нельзя).

## 5. Доступ к консоли (SSH)

### Порт

SSH работает на нестандартном порту (не 22) — меньше автоматического
шума-перебора. Сменить порт можно в карточке «Доступ к консоли», **с подтверждением
паролем** — смена происходит на лету, без разрыва текущей сессии.

> На WAN порт всё равно закрыт фаерволом (см. §1) — заходить по SSH только из
> локалки/VPN.

### Пароль root

Сменить пароль пользователя `root` (вход в консоль/по SSH) — прямо из панели,
карточка «Консоль и SSH». Нужно подтвердить пароль администратора панели, новый
пароль — минимум 6 символов.

### Вход по ключу (надёжнее пароля)

Ключ — это пара файлов: **публичный** (его кладут на сервер) и **приватный**
(секретный, хранится у тебя). Кто не имеет приватного файла — не зайдёт, даже зная
пароль. Поддерживаются **оба способа** одновременно (пароль и ключ).

Два пути завести ключ:

1. **Сгенерировать прямо в панели** (проще всего) — кнопка «Сгенерировать ключ на
   сервере». Сервер создаёт пару, публичную часть добавляет себе сам, а
   **приватный файл скачивается тебе**. На сервере приватный ключ **не хранится** —
   сохрани скачанный файл надёжно. Заходишь так:
   ```
   ssh -i скачанный_файл -p <порт> root@<адрес-шлюза>
   ```
2. **Принести свой** — на своём компьютере `ssh-keygen -t ed25519`, затем
   содержимое `~/.ssh/id_ed25519.pub` (это **публичная** часть, начинается с
   `ssh-ed25519`) вставить в поле «Добавить ключ». Приватный файл никому не давай.

Любой добавленный ключ виден в списке и удаляется одной кнопкой.

## Под капотом (хардеринг)

По итогам пентест-аудита:

- **Пароли панели** хранятся не открытым текстом, а в виде хеша **PBKDF2-HMAC-SHA256**
  (200 000 итераций, индивидуальная соль). Старые пароли мигрируют в хеш при первом входе.
- **Пароль по умолчанию** (`admin`) панель распознаёт и просит сменить.
- **Контейнер веб-панели** запускается без `privileged` — только с минимально
  необходимыми capabilities (управление сетью + вход в namespace хоста). Сужена
  поверхность атаки при компрометации.
- **Заголовки безопасности**: HSTS, CSP, X-Frame-Options DENY, nosniff, no-referrer.
- Команды к хосту (смена пароля, ключи, порт) идут без shell-инъекций (валидация +
  передача данных через stdin).

## Коротко

- Снаружи шлюз закрыт; админ — через VPN.
- Перебор паролей — автоблок, но только атакующих снаружи (своих не тронет).
- Дашборд показывает атаки в реальном времени.
- Модератору можно дать наблюдение без управления.
- SSH — на нестандартном порту (свой у каждой установки), можно сменить пароль root и завести ключи прямо из панели.
