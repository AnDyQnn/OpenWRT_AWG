# Диагностика

[← К содержанию](README.md)

Типовые проблемы и их решение. Большинство видно прямо на экране ПК
(`gateway-status`) или в журнале панели.

---

## Команды диагностики (по SSH или на ПК)

| Команда | Что показывает |
|---------|----------------|
| `gateway-status` | сводный дашборд: система, порты, VPN, контейнеры, аренды, события |
| `watch -n3 gateway-status` | то же, авто‑обновление |
| `gateway-vpn-debug` | диагностика туннеля: endpoint, маршрут к нему, `awg show`, путь MTU |
| `docker ps` | статусы контейнеров (`gw-awg`, `gw-dnsmasq`, `gw-webui` = Up) |
| `journalctl -u gateway-compose -n 30` | лог поднятия контейнеров |
| `tail -f /var/log/awg-watchdog.log` | живой журнал событий |

## Частые проблемы

### Не открывается панель

| Проверь | Решение |
|---------|---------|
| Подключён к LAN‑порту шлюза? | панель из интернета закрыта, только LAN / Wi‑Fi за шлюзом / VPN |
| Адрес | `https://192.168.88.1` (HTTPS!), принять самоподписанный сертификат |
| Контейнер `gw-webui` Up? | `gateway-status` покажет; при сбое печатает лог контейнера на экран |

### VPN жёлтый (fallback) / нет хэндшейка

| Причина | Решение |
|---------|---------|
| Сервер недоступен | проверь endpoint; система пробует каждые 5 мин сама |
| Петля endpoint | `gateway-vpn-debug` — endpoint должен идти **не** через `awg0`; нормализация это лечит |
| Неверный ключ | перезалей `.conf` через панель |

### VPN подключился, но у клиентов нет интернета

| Причина | Решение |
|---------|---------|
| Нет NAT на туннеле | `awg-up` ставит `MASQUERADE -o awg0` автоматически; перезалей конфиг / перезагрузи |
| Большие страницы не грузятся (особенно RU) | MSS‑клампинг ставится автоматически; проверь `iptables -t mangle -S FORWARD` |

### Клиент за роутером не различается правилами

Роутер снизу в режиме **NAT** прячет клиентов за одним MAC — переключи доп. точку
в режим **«точка доступа / мост»**. См.
[Контроль доступа §4](access-control.md#4--устройства-за-вложенным-роутером).

### Блокировка не срабатывает

| Проверь | Решение |
|---------|---------|
| Клиент использует чужой DNS? | DNS форсится на шлюз (DHCP‑option 6 + DNAT :53); глобальный блок — по имени |
| Группа по MAC, а MAC скрыт за роутером | см. выше про NAT‑роутер |
| IP сайта сменился | `↻ адреса` у ресурса / watchdog обновит сам |

### Обход (раздельное туннелирование) не работает

| Проверь | Решение |
|---------|---------|
| Адреса собрались? | у ресурса должны быть `cidrs`; нажми `↻ адреса` |
| Маршрут | `ip route get <адрес>` на шлюзе → должен быть `dev <wan>`, не `awg0` |

### Поменял сетевую карту / порты

Просто **перезагрузи** — `wan-detect` переопределит порты по наличию интернета.

### Устройство показывает скорость 0

Это норма — устройство сейчас ничего не передаёт (простой). Появится трафик —
пойдут реальные цифры.

## Уровни самовосстановления

| Уровень | Период | Действие |
|---------|--------|----------|
| Docker `restart: unless-stopped` | мгновенно | поднимает упавший контейнер |
| `sysmon` | 1 мин | рестарт сервисов, чистка памяти |
| `vpn-watchdog` | 5 мин | failover VPN, рефреш маршрутов/ACL |
| `gateway-init` / `wan-detect` | каждая загрузка | переопределение сети |

Если ничего не помогает — перезагрузка чинит почти всё (система переопределяет
сеть и поднимает сервисы заново).
